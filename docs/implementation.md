# Implementation and verification notes

The adapted `FreedomModel` in `src/mmrec_lab/model.py` follows the pinned [MMRec FREEDOM source](https://github.com/enoche/MMRec/blob/c68ee7c9b0de1ca7c5150258322edb4994be29d9/src/models/freedom.py). The item's image and text kNN graphs are built from the initial feature matrices and then fixed; item feature tables and recommendation parameters remain trainable. The interaction graph is normalized and resampled with degree-sensitive pruning each epoch. The implementation supports image-only, text-only, and joint modes. [The reproduction map](reproduction-map.md) records specific deviations from the paper and upstream code, including CPU random streams and graph edge handling.

## Missing-image inputs

`build_neighbors` binarizes training user–item interactions, counts item co-interactions, removes self-edges, and selects up to 20 neighbors by count with item-ID tie breaks. The result is an unweighted directed sparse graph. `make_missing` uses separate seeds for `clean`, `uniform30`, and `tail30`; the two masks hide `floor(0.3 × item_count)` image vectors. The train split alone defines item popularity and co-interaction neighbors. Hidden rows are zeroed before `impute_features`; no method can read their original vectors. Text and user interactions remain unchanged.

The six implemented methods are `zero_fill`, `global_mean`, `paper_neighmean`, `observed_mean`, `fixed_mix`, and `support_mix`. The paper-style neighbor mean divides the sum of visible neighbor vectors by the *full graph degree*; the observed mean divides by the *visible support count*. They are different when some neighbors are hidden. Zero-degree paper-style output is locally defined as zero. Observed-mean, fixed-mix, and support-mix use the visible global mean when support is zero. Imputation is one pass: a filled vector does not become evidence for another item.

## Ranking and leakage controls

Validation chooses the best epoch using overall Recall@20, with training interactions excluded from candidate rankings. When enabled, test evaluation uses the selected best checkpoint and excludes both training and validation interactions. Development and profile runs disable test evaluation. Scores rank the full item catalog; blocked items are removed, and item ID breaks score ties. Group metrics for all, tail, missing, and tail-and-missing items retain positions from the full ranking rather than reranking within a group. A group with no positives has `null` Recall/NDCG and explicit zero counts.

Each completed training directory records configuration, seed, data and feature hashes, core source hashes, environment versions, epoch history, resource measurements, best checkpoint, and status. A matching completed directory can be reused only after identity and artifact-hash checks. Incomplete runs keep optimizer and random-generator state in `resume.pt` for epoch-boundary recovery. The released repository intentionally excludes these run directories and checkpoints; publishing the five-row summary does not make checkpoint replay possible without rerunning local training.

Historical validation included small deterministic tests for imputation formulas, held-out masking, ranking denominators and blocked interactions, checkpoint recovery, and comparisons against the pinned upstream model's graph, forward scores, loss, and gradients. The pre-main integration run recorded 76 passing tests plus 30 passing subtests. The five real development checkpoints were then independently used to recompute validation rankings, as described in the [interim findings](findings.md). Neither check supplies the unrun 45-condition study or a held-out test result.
